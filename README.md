# Safari Profile Switcher

Приложение для строки меню macOS: переключает окна Safari между профилями, переносит вкладки между профилями и открывает ссылки из других приложений в нужном профиле.

## Возможности

**Переключение профиля (по умолчанию ⌥⇥).**
- Каждое нажатие показывает следующее окно текущего профиля. Когда окна профиля закончились, показывается окно следующего профиля. Профилей может быть больше двух: в «Настройки → Общие» отметьте, между какими переключаться, и задайте порядок. Частный доступ тоже можно включить в этот список.
- Если окон другого профиля нет, открывается новое окно этого профиля через меню Safari «Файл → Новое окно». Новое окно встаёт на место текущего, в том числе в полноэкранном режиме.
- Окно, где открыта только стартовая страница, закрывается. Это можно отключить в настройках.
- Если удерживать ⌥ дольше задержки или нажать ⇥ ещё раз, появится переключатель (HUD), как у ⌘⇥. В нём колонки профилей (включая Частный доступ), а под каждым профилем — его окна. ⇥ и ⌥→ выбирают следующий профиль, ⌥⇧⇥ и ⌥← — предыдущий, ⌥↑ и ⌥↓ — окно внутри профиля, ⌥⎋ отменяет выбор. Отпустите ⌥, чтобы подтвердить, или щёлкните по нужному окну. У профиля без окон есть пункт «Новое окно». Вместо колонок можно показывать список окон. В нём у каждого окна видны его вкладки: ⌥↑/⌥↓ выбирают окно, ⌥←/⌥→ — вкладку в нём, ⌥W дважды закрывает выбранную вкладку. После отпускания ⌥ открывается выбранное окно на выбранной вкладке.
- Вне Safari ⌥⇥ по умолчанию тоже открывает переключатель: так можно сразу выбрать нужный профиль или окно. Если Safari не запущен или у него нет окон, переключатель предложит открыть окно нужного профиля. Быстрое нажатие без удержания возвращает в то окно Safari, которое было впереди, когда вы ушли из Safari (его профиль показан в строке меню), даже если оно свёрнуто.

**Вкладки.**
- **⌃⌥→** переносит текущую вкладку в следующий профиль. Если для сайта есть правило, вкладка уходит в профиль из правила. Переносится только URL: история и cookies остаются в старом профиле. Есть режим «копировать». После переноса в меню появляется пункт «Всегда открывать сайт в профиле…».
- **⌃⌥↑** выносит вкладку в отдельное окно того же профиля. **⌃⌥↓** возвращает её в окно, откуда она пришла. В обоих случаях история вкладки сохраняется.

**Строка меню.**
- Значок показывает профиль переднего окна Safari цветной «таблеткой», как в самом Safari: буква или свой текст на цвете профиля, для Частного доступа — ладонь. Пока впереди другое приложение, значок бледнее и показывает последний профиль. Можно показывать значок с именем профиля или только значок приложения. Текст и цвет задаются для каждого профиля в «Настройки → Общие».
- В меню перечислены окна, сгруппированные по профилям, включая Частный доступ. Щелчок по окну выводит его вперёд. У каждого профиля есть пункт «Новое окно»; если Safari не запущен, он запустит Safari.

**Ссылки.** Приложение можно сделать браузером по умолчанию: «Настройки → Ссылки». Тогда ссылки из других приложений открываются в профиле, который выбирают правила.
- Правило задаётся по сайту и, при желании, по приложению-источнику. `example.com` срабатывает вместе с поддоменами, `*.example.com` только для поддоменов, `github.com/org` задаёт путь. Приложение указывается как bundle id, например `com.tinyspeck.slackmacgap` для Slack.
- Правило может открывать ссылку не в Safari, а в другом приложении: «открыть в → Другое приложение…». Если приложение принимает не https, а свою схему, она подставляется сама. Например, Толк (`kontur.talk`) получает `ktalk://company.ktalk.ru/room` вместо `https://company.ktalk.ru/room`. Ссылки, пришедшие из самого этого приложения, правило пропускает, иначе получился бы цикл.
- Если ни одно правило не подошло, по умолчанию решает сам Safari: ссылка передаётся ему, и он применяет «Настройки → Сайты → Открыть ссылки в профиле» (или самый недавний профиль). Вместо этого можно выбрать профиль по умолчанию или меню выбора профиля. Простые правила «сайт → профиль» удобно держать в Safari, а в приложении — то, чего Safari не умеет: приложение-источник, пути, меню выбора, очистку ссылок. Прочитать правила Safari напрямую нельзя: они лежат в его закрытом контейнере, для этого понадобился бы Полный доступ к диску. Чтобы выбрать профиль вручную, удерживайте ⌥ при клике по ссылке. Если в этом меню удерживать ⌥, выбор запомнится как правило.
- Ссылки-обёртки (Outlook Safe Links, Facebook, Google, VK) разворачиваются, а `utm_*`, `fbclid` и подобные параметры удаляются. Обе функции отключаются по отдельности. Из обёртки берутся только ссылки `http(s)`. Учтите, что развёрнутая Safe Link не проходит проверку Microsoft.

Все шорткаты настраиваются и отключаются на вкладке «Шорткаты». Если назначить сочетание, которое уже занято, действия поменяются сочетаниями. Шорткаты для Safari регистрируются, только пока Safari на переднем плане, поэтому в остальных приложениях эти сочетания свободны. Шорткаты переключателя регистрируются только с первого нажатия ⌥⇥ и до его закрытия. Что делает ⌥⇥ вне Safari, задаётся в настройках.

Логика шорткатов по умолчанию: ⌥ — модификатор профилей (⌥⇥ переключает, в переключателе ⌥ со стрелками перемещает выбор, ⌥⇧⇥ идёт назад), ⌃⌥ со стрелками — действия с вкладкой (⌃, как в ⌃⇥ у Safari для вкладок). Сочетания ⌥⇧ со стрелками не используются: в текстовых полях они выделяют слова и абзацы.

Интерфейс есть на английском и русском, язык берётся из системы.

Профиль окна определяется по заголовку: Safari называет окна `«Профиль» — «Заголовок страницы»`. Окна частного доступа префикса не имеют, по этому признаку они и определяются. Если профиль из настроек или правила пропал из Safari (например, его переименовали), предупреждение появится в меню и в настройках.

Действия с Safari выполняются по очереди. Быстрое двойное нажатие ⌥⇥ переключит дважды, а лишние нажатия, пока Safari занят, отбрасываются со звуком. Если Safari не отвечает 5 секунд, действие прерывается с ошибкой, а приложение не зависает.

## Сборка и установка

Нужны macOS 15+ и Xcode (или Command Line Tools со Swift 6).

```bash
scripts/build-app.sh --install
```

Без `--install` приложение собирается в `build/SafariProfileSwitcher.app`. Версия берётся из файла `VERSION`, номер сборки — из числа коммитов. Приложение подписывается с Hardened Runtime. Иконку можно перерисовать командой `swift scripts/make-icon.swift`.

Чтобы macOS не забывала разрешение Универсального доступа после каждой пересборки, один раз создайте локальный сертификат подписи:

```bash
scripts/create-signing-cert.sh
```

При первой подписи этим сертификатом macOS спросит доступ к ключу в связке ключей. Выберите «Разрешить всегда», иначе `codesign` будет ждать ответа при каждой сборке. Без этого сертификата сборка подписывается ad-hoc. Другую подпись можно задать через `CODESIGN_IDENTITY`; если указанной подписи нет, сборка остановится.

Для распространения нужен Developer ID. Скрипт `scripts/notarize.sh` подписывает приложение, нотаризует его и упаковывает в zip. Инструкция в начале скрипта.

## Разрешения

1. **Универсальный доступ** нужен, чтобы нажимать пункты меню Safari (новое окно профиля, вынос вкладки), поднимать окна и следить за активным окном.
2. **Автоматизация → Safari** нужна, чтобы читать и менять окна и вкладки.

Статус обоих разрешений и версия приложения видны в «Настройки → О программе». Там же есть кнопка «Сохранить диагностику Safari»: она пишет окна и меню Safari в `~/Library/Logs/SafariProfileSwitcher/diagnostics.txt`.

## Разработка

```bash
swift test
```

```bash
swift build && .build/debug/SafariProfileSwitcher --self-test
```

Самопроверка есть только в debug-сборке. Чтобы запустить её внутри `.app`, соберите приложение с `scripts/build-app.sh --self-test`. CI (`.github/workflows/test.yml`) на каждый push запускает юнит-тесты и release-сборку.

- `Sources/SwitcherCore` — вся логика решений, покрытая тестами: переключение по N профилям, перенос вкладок, выбор окна для возврата, HUD и момент его появления, правила и очистка ссылок, конфликты шорткатов, проверка профилей.
- `Sources/SafariProfileSwitcher` — само приложение:
  - хоткеи через Carbon;
  - Safari через одну заранее скомпилированную библиотеку AppleScript-обработчиков и Accessibility;
  - строка меню, HUD, настройки;
  - String Catalog в `Resources`.
- `--self-test` проверяет AppleScript-часть на запущенном Safari. Он создаёт свои временные окна и закрывает их, а ваши окна не трогает. Также проверяются настройки, регистрация хоткеев, меню, маршрутизация ссылок и HUD. Если задать `SPSW_SNAPSHOT_DIR`, самопроверка сохранит PNG с HUD и вкладками настроек. Части, которым нужен Универсальный доступ, проверяются только в установленном приложении.
