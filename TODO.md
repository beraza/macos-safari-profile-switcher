## Отличия от плана

- **Клавиши HUD.** «Следующий» по умолчанию ⌥→, потому что ⌥⇥ (шорткат переключения) и так выбирает следующий элемент. Отдельного ⌥← нет, «назад» — это ⌥⇧⇥. Остальное как в плане.
- **Окно настроек и меню.** `MenuBarExtra` заменён на `NSStatusItem`: меню нужно перестраивать при каждом открытии. Окно настроек теперь обычное `NSWindow` с вкладками «Общие», «Шорткаты», «Ссылки», «Разрешения».
- **Запасной вариант выноса вкладки.** Если в меню «Окно» нет пункта «Переместить вкладку в новое окно» (название берётся из `MainMenu.strings` Safari под текущий язык), открывается новое окно профиля, и вкладка переносится туда через AppleScript `move tab`. История сохраняется и в этом случае.
- **Найдено по ходу.** Safari оставляет закрытые окна в списке AppleScript как невидимые, без вкладок. Видимо, это для «Открыть последнее закрытое окно». Такие окна теперь отфильтрованы. Раньше переключатель мог выбрать «призрака».

## Переключатель, хоткеи, ссылки, частный доступ, строка меню (31.10.2026)

- **Переключатель** показывает колонки профилей с их окнами (логика в `HUDState.profiles`, навигация `step`). ⌥⇥/⌥→ — следующий профиль, ⌥⇧⇥/⌥← — предыдущий, ⌥↑/⌥↓ — окно внутри профиля. Вне Safari ⌥⇥ тоже открывает переключатель (новая настройка, по умолчанию). Без окон или без запущенного Safari переключатель предлагает открыть окно профиля и сам запускает Safari.
- **Хоткеи.** Раньше ⌥⇧⇥ означало и «перенести вкладку», и «назад в переключателе». До появления HUD срабатывал перенос, и вкладка закрывалась. Теперь шорткаты переключателя регистрируются с первого нажатия, а «назад» (`switchBack`) — это всегда шорткат переключения с ⇧. Действия с вкладками переехали с ⌥⇧+стрелки (отнимали выделение текста в полях Safari) на ⌃⌥+стрелки. Добавлены ⌥↑/⌥↓. Если сочетания не меняли, новые подставятся сами: в настройках хранятся только отличия от значений по умолчанию.
- **Ссылки.** Новый вариант по умолчанию для ссылок без правила — «Решает Safari»: ссылка уходит в Safari, и он применяет свою настройку «Открыть ссылки в профиле». Читать или менять эту настройку напрямую нельзя: контейнер Safari закрыт TCC (нужен Полный доступ к диску), а формат не документирован.
- **Частный доступ** — псевдопрофиль `#private`. Его окна — те, у которых нет префикса профиля (проверено: частное окно называется «Частный доступ», без «Профиль — »). Он участвует в переключателе, меню, списке переключения, правилах ссылок и переносе вкладок. Открывается через «Файл → Новое частное окно». Предупреждение «по заголовкам не определить профиль» убрано: окно без префикса теперь означает частное окно.
- **Строка меню.** Цветная «таблетка» профиля (текст и цвет настраиваются), ладонь для частного доступа, бледная, пока Safari не впереди. Варианты: значок приложения, значок профиля, значок с именем.

## Ссылки в других приложениях, возврат в последнее окно (31.10.2026)

- У правила ссылки появилась цель «приложение» (`LinkRule.targetApp`) и его схема (`targetScheme`). Схема определяется сама: если приложение не открывает https, берётся первая схема из его `CFBundleURLTypes`. Толк в коде меняет `https://` на `ktalk://`, поэтому ссылки ему отдаются как `ktalk://host/room`. Правило не срабатывает для ссылок из того же приложения (защита от цикла), такие ссылки идут дальше по правилам. Старые сохранённые правила читаются без изменений.
- Вне Safari быстрое ⌥⇥ (и «Активировать Safari») открывает окно, которое было впереди, когда Safari потерял фокус. Его профиль и показан в строке меню. Раньше Safari просто активировался.

- Профили по номеру: ⌥1…⌥9 и ⌃⌥1…⌃⌥9 (`HotKeyCommand`), модификаторы настраиваются, сочетания действий имеют приоритет.
- Поиск по вкладкам всех профилей (⌃⌥F, `TabSearch` в ядре, `TabSearchPanel`).
- Действия в переключателе: закрыть вкладку/окно (⌥W/⌥⇧W дважды), перенести вкладку/окно (⌥M/⌥⇧M), вынести вкладку (⌥D). Перенос окна целиком (⌃⌥⇧→, `WindowTransfer`).
- Вкладки выбранного окна видны и в режиме колонок; ⌥↑/⌥↓ идут по вкладкам, затем к следующему окну.
- «О программе»: «Проверить работу» (`LiveCheck`), экспорт и импорт настроек (при импорте шорткаты без модификатора отбрасываются, значки и задержка обрезаются до допустимого).
- Настройки переключателя вынесены на вкладку «Переключатель»; список правил ссылок прокручивается сам, если правил больше пяти.

Проверка кода (10 замечаний, все исправлены): возврат в последнее окно теперь берёт окно через Универсальный доступ в момент нажатия, без Apple Event к Safari при каждом уходе из него (мог подвесить приложение или перезапустить закрывающийся Safari); панель поиска растёт вниз от верхнего края, получает фокус при каждом открытии, ↑/↓ ловятся монитором клавиш; ⌥D из переключателя ждёт активации Safari; предзагрузка не берёт устаревшие окна, пока выполняется действие; занятые номерные шорткаты видны в настройках; убраны дубли.

Безопасность:
- Входящие ссылки: принимаются только `http`, `https` и HTML-файлы. Любое приложение может прислать событие «открыть URL» напрямую, поэтому `javascript:` и прочие схемы игнорируются. Из ссылок-обёрток берутся только `http(s)`.
- AppleScript получает параметры дескрипторами, а не подстановкой в текст скрипта, поэтому внедрение кода через заголовки или адреса невозможно.
- Горячие клавиши — через Carbon `RegisterEventHotKey`, без мониторинга ввода; модификаторы читаются как состояние, нажатия не записываются. Импорт настроек отбрасывает шорткаты без модификатора, чтобы файл не мог перехватить обычный ввод.
- Универсальный доступ используется только для процесса Safari.
- Диагностика больше не пишет на диск заголовки и адреса окон частного доступа. Журнал пишет ссылки с `privacy: .private`.
- Подпись: Hardened Runtime, единственное право — Apple Events. Ключ локального сертификата создаётся во временной папке и удаляется, доступ к нему есть только у `codesign`.
- Осталось: в CI `actions/checkout@v4` указан по тегу, а не по хешу коммита.
